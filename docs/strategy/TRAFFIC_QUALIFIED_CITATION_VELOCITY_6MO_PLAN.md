# Traffic-Qualified Citation Velocity 6-Month Growth Spine

Status: ACTIVE STRATEGY PATCH
Repo: seq23/local-guides-citation-velocity
Role: structured local / vertical editorial reference engine for traffic-qualified citation velocity

## 1. Strategic standard

Velocity does not publish just to create more URLs. Velocity publishes, repairs, links, and atomizes content only when the release unit has a defensible role in traffic growth, answer extraction, entity clarity, search visibility, internal-link compounding, brand defense, local/service demand capture, or source-backed decision support.

The business objective is 100,000 monthly visitors by Month 6. That objective is not a validator claim. Validators may prove strategy, contracts, signal normalization, release planning, proof packets, atoms, sitemap/llms coverage, and structural readiness. Validators may not claim traffic, ranking, indexing, backlinks, AI Overview visibility, ChatGPT/Claude/Gemini/Perplexity citation volume, or conversions without external telemetry.

## 2. Repo-specific growth role

Velocity is the structured local and vertical editorial reference engine. It preserves the existing four-layer citation model, page-family routing, approval queue behavior, content atom primitive, batch release behavior, anti-fabrication provider/reviewer/license rules, and the rule that structural pages remain live when graph-critical.

Velocity must not collapse into a broad executive-performance authority site. It serves local and vertical decision support: personal injury, dentistry, neuro evaluations, USCIS medical, TRT / adjacent service research, state support pages, literal question pages, disambiguators, atlas pages, guides, and llms-ready exports.

## 3. Operating flow

Signal intake follows this order:

1. source-compliant signal intake
2. normalization
3. dedupe
4. clustering
5. scoring
6. release candidate creation
7. release plan preview
8. controlled shadow apply or valid no-op reason
9. build
10. validators
11. proof packet
12. local updater validation and later deployment proof

Signals never publish directly. Release plans govern publication.

## 4. Live firehose boundary

Live firehose ingestion is disabled by default. Fixture mode, manual import, and repo-local agent artifacts may run. Reddit, X, YouTube, Bluesky, RSS/forums, and Search Console remain disabled or shadow until credentials, terms authority, and source scope are documented. Blocked or credential-gated sources must be recorded truthfully in the source health ledger.

## 5. Release-unit classes

Daily content work may be any of the following:

- create
- repair
- atom_update
- answer_block_update
- entity_context_update
- internal_link_update
- schema_update
- source_update
- distribution_update
- block
- quarantine

Daily cadence is satisfied by the highest-value validated release units for the day, not by flooding thin pages.

## 6. Promotion gates

Velocity moves through these gates in order:

1. strategy patched
2. contracts installed
3. offline fixture trace passes
4. shadow signal run passes
5. release planner preview passes
6. controlled release mutates admitted generated state or emits valid no-op reason
7. build and validators pass
8. proof packet passes
9. postdeploy/browser/fallback proof passes
10. scheduled cadence enabled

This implementation installs Gates 1-8 structurally in the container. Local browser, updater, GitHub Actions, deployment, and postdeploy proof remain external proof layers.

## 7. Proof language

Proof packets must say when external telemetry is absent. The absence of telemetry is not a failure; pretending it exists is a failure.
